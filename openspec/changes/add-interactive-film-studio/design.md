# Design

## Context

短剧根据章节建立集，集持有连续镜头、可重建的剧情段和最终资源。互动剧本在制作前已经有场次和出口，需保留场次身份。

## Goals / Non-Goals

首版面向作者，支持直接选项、自动续播与多个结局。公开发行、复杂变量与存档属于后续扩展。

## Decisions

- 独立影游记录按用户归属保存原著、改编方向、剧情图和版本号。场次 ID 稳定，引用可重建的镜头或段序会破坏连线。
- 提炼 Story-to-game 的原著分析、改编方向对齐、分支汇合和结局设计方法，通过系统文本任务生成影视场次，提示词按场次控制规模。
- 以同一制作项目下的一集承载一个投产场次，复用剧本来源模式、共享角色资产和手动媒体生成。用事务记录场次对应的集，允许补投其他场次。投产保存剧本快照，以便后续区分已拍内容和改稿。
- 完整作品默认进入影游制作台。左侧按 DAG 导航，右侧复用短剧的剧本、分镜、成片及剧情段精修组件。地址记录场次与打开的剧情段，浏览已保存的剧本无需投产。
- 保存草稿与执行校验分开。选择规则由后端在投产时重新校验，浏览器试玩也校验当前编辑内容。多入口场从共同前情起拍。

## Risks / Trade-offs

- 模型可能生成断边或回环。生成后提供可定位的校验反馈，允许手工改图。
- 多窗口覆盖或重复投产。使用版本条件写入，交接映射与制作单元原子提交。

## Migration Plan

数据库添加影游记录表，现有短剧项目无需回填。回退应用版本即可停用新入口，保留已创建作品。
