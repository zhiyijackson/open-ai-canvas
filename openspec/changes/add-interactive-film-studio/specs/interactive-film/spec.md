# Spec Delta

## Purpose

帮助编剧将小说转成具有选择、汇合和多个结局的互动影片，先通过文字试玩验证叙事，再将独立场次交给现有影视制作流程，通过同一剧情图预览已经生成的视频。

## ADDED Requirements

### Requirement: 小说改编

系统 SHALL 接受小说文本，让作者调整改编方向后生成可编辑的分支剧本。

#### Scenario: 上传原著后对齐方向

- **WHEN** 作者上传小说并生成改编方向
- **THEN** 作者可调整方向，再发起剧情图生成

### Requirement: 剧情图与试玩

系统 SHALL 保存稳定的场次身份、唯一入口、续播、选择和结局，试玩前验证整张图可达、无环且能抵达结局。

#### Scenario: 汇合与结局

- **WHEN** 两条选择通向同一场次
- **THEN** 试玩从各路径进入同一场，播完后按该场的出口继续

#### Scenario: 无效图

- **WHEN** 剧本含有回环、悬空出口或不可达场次
- **THEN** 系统说明错误并阻止按该图执行制作

### Requirement: 场次制作

系统 SHALL 按照独立场次复用短剧分镜与视频制作，保留场次到制作单元的对应关系。

#### Scenario: 在同一制作台切换场次

- **WHEN** 作者从作品库打开完整剧情图，在左侧 DAG 中选择场次
- **THEN** 右侧显示该场的剧本、分镜或成片，选择节点本身不提交制作任务

#### Scenario: 精修场次的剧情段

- **WHEN** 作者在影游分镜页点击一个已生成的剧情段
- **THEN** 系统在当前影游中打开短剧共用的剧情段弹窗，刷新能恢复同一场次与剧情段

#### Scenario: 重复进入制作

- **WHEN** 作者再次打开已投产场次
- **THEN** 系统打开同一制作单元，完成的场次视频可在剧情试玩中播放

### Requirement: 作品归属与修改冲突

系统 SHALL 隔离用户作品，并在写入旧版本时返回冲突。

#### Scenario: 多个编辑窗口

- **WHEN** 两个窗口从同一版本修改剧本并先后保存
- **THEN** 先保存的版本保留，另一窗口得到冲突提示

#### Scenario: 跨账号访问

- **WHEN** 另一账号使用作品 ID 读取或投产
- **THEN** 系统拒绝访问
